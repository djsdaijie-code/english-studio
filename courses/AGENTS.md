# 课程内容开发规范

本文件是 `courses/` 下内置课程内容开发的最高规范。发生冲突时，课程 JSON、模板和内容修改必须以本文件为准；软件仓库其他规范仍管理通用代码与发布流程。

## 1. 适用范围

本规范负责专题课程、Level、Unit、每日课程（Day/Lesson）、句子及其他 Learning Item、翻译、词汇、句型、自测和课程静态数据。它不负责软件底层功能、数据库实现、UI 开发、打包、GitHub 发布或通用 Bug 修复。

## 2. 课程层级

固定层级为：

```text
Course → Level → Unit → Day → Learning Item
```

- Course 定义产品定位、默认学习计划和 Level。
- Level 定义难度阶段和 Unit 顺序。
- Unit 是独立内容文件，定义 Day、句子和可覆盖的学习计划。
- Day 使用 `lesson` 数据表示，是可安排、可完成、可复习的每日学习单元。
- Learning Item 包括句子、词汇、活动、阅读材料和测评；第一版样例以句子为主。

不得退化为“课程—句子”的扁平结构。数组顺序仅用于展示，不能代替 ID。

## 3. 每日学习规则

- 默认每天 6 个新句子，建议最多不超过 8 个。
- 默认 Unit 为 7 天：Day 1–4 学新句，Day 5 综合场景，Day 6 听写与跟读，Day 7 复习与测评。
- 每个 Unit 必须包含复习；复习日原则上不增加新句。
- 默认参数为 `new_sentences_per_day: 6`、`unit_days: 7`、`review_day: 7`、`dictation_day: 6`、`assessment_day: 7`。
- 默认参数写在课程数据中，不得硬编码进软件逻辑或 JSON Schema。Unit 可通过 `learning_plan_override` 覆盖一个或多个参数。
- 初级句优先 4–8 个英文单词，中级句优先 8–15 个，高级句优先 15–25 个；这是内容审核指引，不是机械截断规则。
- 每日陌生词数量必须受控；同一 Day 的新技术词应围绕一个场景。
- 句型应从直接命令、简单陈述逐步过渡到条件、原因、比较和多步骤说明。

## 4. 英语质量规范

内容必须自然、真实、高频、技术事实正确，并符合真实软件或技术场景。必须统一大小写和英文标点，不使用中式英语，不做机械直译，不为凑词汇而拼句，也不得只替换名词批量制造近义句。

每个句子应有清楚的交际目的。短句可以重复高频句型，但场景或语义功能必须产生真实变化。技术内容避免绑定某个厂商的短期 UI 文案、型号或价格。

## 5. 大小写规范

下列名称使用固定形式：

```text
AI
API
JSON
Python
Linux
Git
GitHub
OpenAI
ChatGPT
English Studio
```

不得写成 `Github`、`Api`、`Json`、`python` 或 `english studio`，除非句首规则或代码原文明确要求其他形式。审核时同时检查标题、场景、词汇、句型和正文。

## 6. 中文翻译规范

- 准确表达原句实际含义，不机械逐词翻译。
- 不增加原文没有的信息，不替用户解释未表达的意图。
- 技术术语在同一课程中保持一致，同类句型保持稳定译法。
- 中文应自然、简洁；按钮动作根据真实语境使用“点击”“选择”“上传”“复制”等明确动词。
- 翻译修订通常只提升 `content_version`，不得因中文润色改变句子的稳定键。

## 7. 难度判定规范

难度不能只看单词数，还必须综合陌生词数量、技术概念、语法结构、从句数量、抽象程度、上下文依赖以及是否包含错误信息或技术说明。句子短但包含 `rate limit`、`authentication` 等概念时，不应误标为初级。

难度枚举为：`beginner`、`elementary`、`intermediate`、`upper_intermediate`、`advanced`。一个 Unit 的主难度应与所属 Level 一致，少量复习句可低一级。

## 8. 重复规范

有价值重复包括：高频句型在不同真实场景中再现；同一核心动词表达不同语义；为听写、跟读和 FSRS 有计划地复现。

无价值重复包括：仅机械替换名词；句子功能完全相同；只为达到数量要求增加内容。审核人应比较 `english`、场景、核心句型和学习目的，而不是只做全文去重。

## 9. 稳定 ID 规范

每个 Course、Level、Unit、Lesson 和 Sentence 必须有机器 ID 与 `stable_key`。格式只使用小写 ASCII 字母、数字和连字符。推荐：

```text
course_id: ai-large-models
level_id: ai-l1
unit_id: ai-l1-u01
lesson_id: ai-l1-u01-d01
sentence_id: ai-s0001
stable_key: ai-large-models-sentence-0001
```

ID 和 `stable_key` 一经发布均视为不可变。`stable_key` 是跨课程包版本关联用户状态的权威键；它不得来自数据库自增 ID、数组下标、全文哈希、文件路径或临时顺序。路径和顺序改变时仍保留原键。

以下修改不得改变 `stable_key`：英文的拼写或标点修正、未改变核心语义的小幅措辞调整、中文翻译调整、场景说明调整、Unit/Day 顺序变化、标签补充和课程包升级。

核心交际意图、目标答案或学习概念发生实质变化时必须创建新键。旧内容改为 `deprecated`，保留原键，绝不复用；可用 `replacement_stable_keys` 指向替代项。

- 拆分：旧项设为 `deprecated`；若其中一项明确延续原核心语义，该项可保留旧键，其他项使用新键。无法判断主继承项时，两项均用新键并记录为旧项的替代。
- 合并：合并项使用新键，所有旧项设为 `deprecated` 并指向新键。
- 删除：已发布项不从历史课程包中抹除；当前包至少保留弃用记录或迁移清单。未来 SQLite 映射也不得删除相应用户状态。

## 10. 数据字段规范

- 必填字段以 `courses/schema/` 中 Schema 的 `required` 为准；模板必须覆盖全部必填字段。
- 可选字段只有 Schema 明确允许时才能出现。当前句子的 `replacement_stable_keys` 为可选字段。
- `description`、`subtitle`、`review_group` 和数组可以为空；正式发布内容的标题、英文、中文和场景不得为空。
- 数组字段保持确定顺序；带 ID 的数组还必须满足 ID 唯一，不能依赖数组下标寻址。
- 枚举值不得自行扩展；需要新增时先修改规范和 Schema。
- 版本使用语义化版本。`specification_version` 记录数据契约，`course_version` 对应课程 `version`，`content_version` 记录具体内容修订。

## 11. 内容审核流程

每批内容至少检查：

1. 场景价值
2. 英语自然度
3. 技术准确性
4. 大小写
5. 标点
6. 难度
7. 重复
8. 中文翻译
9. 朗读适配
10. 听写适配
11. FSRS 适配
12. JSON Schema 校验

进入 `reviewed` 前必须由内容审核者逐句检查；进入 `published` 前还必须验证所有 ID、引用、路径、版本和课程计划一致。

## 12. 版本管理

- `specification_version`：Schema 与字段契约版本。文档澄清不改变它；兼容地增加可选字段提升次版本；删除字段、改变类型或语义等破坏性结构变化提升主版本。
- `course_version`（JSON 字段为 `version`）：课程包发行版本。增加 Unit 或显著调整学习路径提升次版本；只修正内容提升补丁版本；破坏兼容的课程重构提升主版本。
- `content_version`：课程、Unit、Lesson 或 Sentence 的内容修订版本。翻译、标点和不改变语义的修正提升补丁；新增兼容内容提升次版本；改变核心语义时原则上创建新稳定键，而不是只提升主版本。

文档修正若不改变数据或内容，无需提升课程内容版本。字段增加必须同步 Schema、模板、README 和样例；字段删除或破坏兼容的结构变更必须经过独立架构任务。

## 13. Codex 工作规范

- 修改 `courses/` 前先完整阅读本文件。
- 不大规模生成未经审核的句子；每批新内容控制在 20–30 句以内，先做小批次质量检查。
- 不自行改变课程定位，不自行删除稳定 ID，不自行修改已发布内容的核心含义。
- 调整课程结构时同步更新计划、文档和版本。
- 所有 JSON 必须通过 Schema 校验；同时检查 ID、`stable_key`、引用路径和固定大小写。
- 课程静态 JSON 不得写入用户进度、FSRS 状态、收藏、笔记、听写记录或跟读记录。
- 本目录任务不得顺带修改数据库 schema、UI、打包或无关功能；需要这些改动时另开实施阶段。
